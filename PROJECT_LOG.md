## 📌 1. Project Overview & Problem Statement
In large events (weddings, corporate conferences, college festivals), professional photographers capture thousands of high-resolution images. Traditional post-event delivery forces attendees to manually browse through endless galleries—a process known as the **"Digital Haystack" problem**.

**The Instant Gallery** replaces manual browsing with an automated **Deep Learning Facial Retrieval Pipeline**:
1. Event photographers bulk-upload photos.
2. The AI system runs **Face Detection** (MTCNN) and converts detected faces into **512-dimensional continuous feature vectors** (FaceNet).
3. Attendees upload a single selfie query or take a live camera selfie.
4. The system computes **Cosine Similarity** between the selfie vector and stored face vectors to deliver a personalized gallery in seconds.

## 🔬 2. Core Deep Learning Theory & Mathematical Formulations

### A. Face Detection & Alignment (MTCNN)
Before extracting features, face regions must be detected and normalized. We use **MTCNN (Multi-Task Cascaded Convolutional Networks)** consisting of three cascaded neural stages:
1. **Proposal Network (P-Net)**: A fully convolutional network that proposes candidate facial bounding boxes and bounding box regression vectors.
2. **Refine Network (R-Net)**: A CNN that rejects false positives generated by P-Net.
3. **Output Network (O-Net)**: Performs final bounding box refinement and identifies 5 key facial landmarks: Left Eye, Right Eye, Nose, Left Mouth Corner, Right Mouth Corner.
4. **Affine Warping & Crop**: The face crop is resized to $160 \times 160$ pixels and normalized:
   $$\hat{X} = \frac{X - 127.5}{128.0}$$

---

### B. Metric Learning & Feature Embedding (FaceNet / Inception-ResNet)
Standard CNN classification models output probabilities across fixed classes (e.g., ImageNet 1000 classes). Face recognition requires **Metric Learning**, where the network functions as a feature extractor:
$$f(x) \in \mathbb{R}^{512}, \quad \|f(x)\|_2 = 1$$

The network maps an input image $x$ to a 512-dimensional point on a unit hyper-sphere such that:
- Images of the **same person** map to points close together in Euclidean space.
- Images of **different people** map to points far apart.

---

### C. Triplet Loss Optimization
The FaceNet backbone (Inception-ResNet-v1) is trained using **Triplet Loss**. Each training instance consists of three samples:
- **Anchor ($A$)**: Image of a specific person.
- **Positive ($P$)**: A different image of the *same* person.
- **Negative ($N$)**: An image of a *different* person.

The objective function minimizes the distance $d(A, P)$ while maximizing $d(A, N)$ by enforcing a margin $\alpha > 0$:

$$\mathcal{L} = \max\left(0, \; \|f(A) - f(P)\|_2^2 - \|f(A) - f(N)\|_2^2 + \alpha\right)$$

```
     BEFORE TRAINING                           AFTER TRAINING
     
       (Positive)                                  (Positive)
           P                                           P
          /                                            |  d(A,P) < d(A,N)
         /                                             |
   A ───┘                                        A ────┘
 (Anchor)  \                                   (Anchor)
            \                                              \
             N                                              N
         (Negative)                                     (Negative)
```

---

### D. Vector Similarity Metric (Cosine Similarity)
Given query selfie vector $\mathbf{u} \in \mathbb{R}^{512}$ and indexed event face vector $\mathbf{v} \in \mathbb{R}^{512}$, we compute the normalized inner product:

$$\text{Similarity}(\mathbf{u}, \mathbf{v}) = \cos(\theta) = \frac{\mathbf{u} \cdot \mathbf{v}}{\|\mathbf{u}\|_2 \|\mathbf{v}\|_2}$$

Since vectors are L2-normalized ($\|\mathbf{u}\| = \|\mathbf{v}\| = 1$), Cosine Similarity simplifies to the dot product:
$$\text{Similarity}(\mathbf{u}, \mathbf{v}) = \mathbf{u}^\top \mathbf{v} \quad \in [-1, 1]$$

---

### E. Similarity Threshold & The Precision-Recall Trade-Off
The **Similarity Threshold** ($\tau$) is the decision boundary for declaring a match:
$$\text{Match}(\mathbf{u}, \mathbf{v}) = \begin{cases} \text{True} & \text{if } \text{Similarity}(\mathbf{u}, \mathbf{v}) \ge \tau \\ \text{False} & \text{otherwise} \end{cases}$$

| Threshold ($\tau$) | Metric Effect | Practical Meaning |
| :--- | :--- | :--- |
| **High ($\tau \ge 0.60$)** | High Precision, Low Recall | **Strict Matching**: Only returns photos where the model is 100% confident. Prevents false positive guest photos (Low False Acceptance Rate - FAR). |
| **Optimal ($\tau = 0.40$)** | Balanced Precision & Recall | **Standard Event Mode**: Recommended baseline for normalized 512-d FaceNet embeddings. |
| **Low ($\tau \le 0.30$)** | High Recall, Low Precision | **Broad Search**: Captures side profiles, low-light shots, and crowd backgrounds (Low False Rejection Rate - FRR), but may include similar-looking guests. |

### Step 2: Environment Configuration & Sample Dataset Generator
- **Goal**: Prepare dependencies and generate sample synthetic event photos and query selfies for immediate out-of-the-box pipeline validation.
- **Code File**: `create_sample_data.py`
- **Output**:
  - `data/event_gallery/`: Group event photos (`event_photo_01.jpg`, `event_photo_02.jpg`, `event_photo_03.jpg`).
  - `data/test_selfies/`: Attendee query selfies (`selfie_alice.jpg`, `selfie_bob.jpg`).

---

### Step 3: Core AI Engine (`backend/ai_engine.py`)
- **Goal**: Implement face detection and embedding extraction using PyTorch MTCNN and Inception-ResNet FaceNet.
- **Key Methods**:
  - `detect_faces(image_path)`: Uses MTCNN to locate face bounding boxes `[x1, y1, x2, y2]`.
  - `extract_embedding(face_crop)`: Pre-processes crop to $160 \times 160$, passes tensor through FaceNet model, L2-normalizes output to 512-d vector.
  - `cosine_similarity(vec1, vec2)`: Computes metric similarity between vector embeddings.

---

### Step 4: Vector Indexing Engine (`backend/indexer.py`)
- **Goal**: Pre-process bulk event photos, extract face embeddings for all individuals present, and build persistent JSON vector index (`data/indexed_db/embeddings.json`).
- **Key Methods**:
  - `index_gallery()`: Iterates through event gallery, detects all faces, extracts 512-d vectors, and writes metadata.
  - `search_by_selfie(selfie_path, similarity_threshold)`: Extracts query embedding from selfie, calculates cosine similarity against all stored embeddings, and sorts matches by confidence.

---

### Step 5: Web API Backend Server (`backend/app.py`)
- **Goal**: Expose high-performance REST API endpoints using FastAPI and Uvicorn.
- **Dependencies**: `fastapi`, `uvicorn`, `python-multipart`, `pydantic`.
- **Endpoints**:
  - `GET /`: Health check & PyTorch FaceNet status.
  - `GET /api/gallery`: Returns indexed photos and face counts.
  - `POST /api/upload-gallery`: Handles bulk image uploads from event photographer and auto-triggers re-indexing.
  - `POST /api/search-selfie`: Receives attendee selfie, executes similarity query, and returns matching photo URLs with confidence scores.

---

### Step 6: Interactive Web Application (`frontend/index.html`)
- **Goal**: Build a modern, single-page web interface with glassmorphism styling, responsive tabs, and dynamic API integration.
- **Features**:
  - **Attendee Portal**: Selfie upload, similarity threshold slider ($0.20 - 0.80$), real-time matching gallery grid.
  - **Photographer Portal**: Event statistics dashboard, drag-and-drop bulk file uploader, indexed payload preview.
  - **DL Theory & Math Explainer**: Interactive reference breakdown explaining MTCNN, Triplet Loss, and Cosine Similarity for class presentations.

---

### Step 7: Application Launcher (`run_app.py`)
- **Goal**: Provide a one-click launcher that launches the FastAPI backend server on `http://127.0.0.1:8000` and automatically opens `frontend/index.html` in the user's web browser.

---

### Step 8: High-Precision MTCNN Landmark Alignment & DBSCAN Identity Clustering
- **Problem**: Uploading 48 photos containing 7-8 distinct people generated 57 raw, unorganized face vectors (due to unaligned bounding box cropping and background noise), leading to noisy selfie search results.
- **Solution**:
  1. **Landmark Affine Alignment (`backend/ai_engine.py`)**: Extracted aligned facial tensors directly from MTCNN (`mtcnn(img)`), enforcing pose-invariant $160 \times 160$ alignment before passing into Inception-ResNet FaceNet.
  2. **DBSCAN Person Clustering (`backend/indexer.py`)**: Implemented Cosine Distance DBSCAN ($\epsilon = 0.38$) to aggregate 26 high-precision face detections into **7 Unique Person Identities**, extracting avatar thumbnails (`data/person_thumbnails/person_X.jpg`) and cluster centroids.
  3. **Multi-Shot Selfie Search & Threshold Calibration (`backend/indexer.py`)**: Calibrated default similarity threshold to 0.55 and enabled multi-shot identity centroid matching.
  4. **Photographer Roster UI (`frontend/index.html`)**: Created interactive Person Roster cards allowing photographers and attendees to view and filter photos by specific recognized person identities.

---

### Step 9: Custom Folder/Album Management & Photo/Folder Deletion Engine
- **WHY We Made This Change**: Photographers managing real events need sub-galleries (e.g. Wedding, Reception, Haldi) to categorize photos. Previously, all photos were dumped into a single flat directory with no option to delete accidental uploads or clear entire albums.
- **HOW We Implemented It**:
  - **Backend REST API (`backend/app.py` & `backend/indexer.py`)**:
    - `POST /api/folders`: Creates custom event sub-directories under `data/event_gallery/{folder_name}`.
    - `DELETE /api/folders/{folder_name}`: Recursively removes specified sub-directory and contents, automatically triggering vector index cleanup and DBSCAN re-clustering.
    - `POST /api/upload-gallery`: Added `folder_name` form parameter to upload files into target event folders.
    - `POST /api/delete-photo`: Deletes individual photo files by relative path (`rel_path`).
    - `POST /api/clear-all`: Safely resets the entire event gallery.
  - **Frontend UI (`frontend/index.html`)**:
    - Interactive **Folder Chips Bar** displaying album names with live photo counters and one-click folder delete buttons.
    - Dropdown target folder selector for drag-and-drop bulk uploads.
    - Individual delete action (`🗑️ Delete`) on every photo card.
